# DAY 2 학습 정리 — ESP32 + MPU-6050 (6축 IMU)

> 목표: 브레드보드에 ESP32와 MPU-6050(GY-521)을 연결하고, I2C 통신으로 센서 값(가속도·자이로·온도)을 읽어낸다.
> 결과: `찾음: 0x68` → 6축 IMU 데이터 출력 성공.

---

## 1. 오늘 만든 것

센서 → MCU → 출력

```
[MPU-6050 센서] --(I2C: SDA/SCL)--> [ESP32 (MCU)] --(USB 시리얼)--> [PC 화면]
```

- **MPU-6050 (GY-521)**: 6축 IMU. 가속도 3축 + 자이로 3축 (+ 온도). I2C로 통신.
- **ESP32**: 두뇌 역할(MCU). 센서에서 값을 받아 시리얼로 출력.
- **브레드보드**: 납땜 없이 부품을 꽂아 연결하는 실험용 기판.

---


## 2. 배선 (I2C 4선 연결)

기본 동작에는 4개 핀만 필요. 나머지(XDA, XCL, AD0/ADD, INT)는 연결 안 함.

| MPU-6050 핀 | ESP32 핀 | 역할 | 선 색(예시) |
|---|---|---|---|
| VCC | 3V3 또는 VIN | 전원 | 빨강 |
| GND | GND | 접지 | 회색 |
| SCL | D22 | I2C 클럭 | 파랑 |
| SDA | D21 | I2C 데이터 | 초록 |

### 배선 체크포인트
- **전원은 VCC + GND 둘 다** 이어져야 들어온다. 하나만 있으면 안 켜짐.
- GY-521은 보드에 레귤레이터가 있어 **VIN(5V)로도, 3V3으로도** 동작. 5V가 더 안정적일 때도 있음.
- 전원이 정상이면 모듈의 작은 **빨간 LED**가 켜진다 → 전원 확인용으로 유용.
- 각 선은 해당 핀과 **정확히 같은 세로줄**에 꽂혀야 한다(한 칸만 어긋나도 연결 안 됨).

## 3. 프로그래밍 개념

### I2C 통신
- 두 가닥(SDA=데이터, SCL=클럭)으로 여러 장치를 연결하는 통신 방식.
- 각 장치는 고유 **주소**를 가진다. MPU-6050의 기본 주소는 `0x68` (AD0 핀을 HIGH로 두면 `0x69`).
- ESP32의 기본 I2C 핀: **SDA=GPIO21(D21), SCL=GPIO22(D22)**.

### Wire 라이브러리 (아두이노 I2C)
- `Wire.begin(SDA, SCL)` — I2C 시작, 핀 지정.
- `Wire.beginTransmission(주소)` / `Wire.write(...)` / `Wire.endTransmission()` — 장치에 명령 쓰기.
- `Wire.requestFrom(주소, N)` / `Wire.read()` — 장치에서 N바이트 읽기.

### 레지스터와 raw 데이터
- 센서 내부는 **레지스터**(주소 붙은 저장칸)로 구성. 원하는 데이터의 시작 주소를 지정하고 순서대로 읽는다.
  - `0x6B`: 전원관리 → 0을 쓰면 절전모드 해제(센서 깨우기).
  - `0x3B`부터: 가속도(6바이트) → 온도(2바이트) → 자이로(6바이트), 총 14바이트가 연속.
- 읽은 값은 2바이트를 합쳐 만든 **raw 정수**. 이걸 물리 단위로 나눠줘야 의미가 생긴다.
  - 가속도: `raw / 16384.0` → g 단위
  - 자이로: `raw / 131.0` → °/s 단위
  - 온도: `raw / 340.0 + 36.53` → ℃

### 데이터의 층위 (IMU 이해)
1. raw 데이터(레지스터 원본 숫자)
2. 물리 단위 변환 ← **오늘 도달한 지점** (g, °/s, ℃)
3. 자이로까지 합친 완전한 6축 데이터
4. 자세 추정(roll/pitch/yaw) — 상보필터·칼만필터로 가속도+자이로를 합쳐야 나옴. 로봇·드론이 자세 잡는 원리.

### 가속도계 vs 자이로 (측정 대상이 다름)
- **가속도계**: 지금 어떻게 기울어져 있나(정적 자세). 가만히 두면 한 축이 1.0g(중력).
- **자이로**: 지금 얼마나 빨리 도나(회전 속도). 가만히 두면 0, 돌리는 순간에만 값이 튐.

## 4. 디버깅에서 배운 것 

| 증상 | 원인 | 해결 |
|---|---|---|
| `'Serial' was not declared` | PlatformIO는 `Arduino.h`를 자동 포함 안 함 | 파일 맨 위에 `#include <Arduino.h>` |
| 시리얼 모니터에 깨진 글자 | 보드레이트 불일치 | `Serial.begin`과 모니터 속도를 **115200**으로 통일 |
| `I2C 스캔 시작`은 뜨는데 `못 찾음` | 통신선(SDA/SCL) 문제 | **SDA↔SCL 스왑** 시도 (가장 흔한 원인) |
| 모듈에 불 안 들어옴 | 전원(VCC/GND) 문제 | 전원 라인·같은 세로줄·선 단선 확인 |
| `multiple definition of setup()` | `src` 폴더에 `setup()` 가진 `.cpp`가 2개 | src엔 메인 파일 하나만 남기기 |

### 핵심 디버깅 전략
- **I2C 스캐너**로 "장치가 잡히나?"부터 확인 → 배선 문제인지 코드 문제인지 분리.
- **부팅 로그**를 읽어 ESP32가 정상 부팅했는지, 코드가 실행됐는지 구분.
- 문제를 **전원 / 통신 / 코드**로 나눠 하나씩 좁혀나가기.

## 5. 오늘 쓴 명령어 (PlatformIO)

```bash
pio run                        # 빌드만
pio run --target upload        # 빌드 + 보드에 업로드
pio device monitor --baud 115200   # 시리얼 모니터 열기
pio run --target clean         # 빌드 캐시 청소 (이상한 에러 지속될 때)
```

- 규칙: `src` 폴더 안에는 `setup()`/`loop()`을 가진 파일이 **딱 하나**만 있어야 한다.
- 모니터 열고 보드의 **EN(리셋) 버튼**을 누르면 처음부터 다시 출력된다.

### platformio.ini 기본형
```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
```
